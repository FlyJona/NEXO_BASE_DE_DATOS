# Auditoría de la base de datos: MySQL → PostgreSQL

Fuente de verdad: [`nexo/database/nexo.sql`](../database/nexo.sql) (MySQL/MariaDB de XAMPP, motor InnoDB, `utf8mb4_unicode_ci`)
y las consultas de la app PHP en `nexo/`. Resultado: [`migrations/`](../../migrations).

## 1. Inventario del esquema de origen

| Elemento | Hallazgo |
|---|---|
| Tablas | 10: `usuarios`, `recuperaciones`, `perfiles`, `materias`, `usuario_materias`, `publicaciones`, `adjuntos`, `comentarios`, `votos`, `guardados` |
| Llaves foráneas | 13; todas `ON DELETE CASCADE` salvo `publicaciones.materia_id` (`ON DELETE SET NULL`); `ON UPDATE` por defecto (`RESTRICT`) |
| Únicos | `usuarios.correo`, `recuperaciones.token_hash`, `materias (nombre, carrera)` — sin distinguir mayúsculas por la intercalación |
| Índices | `publicaciones.creado_en`, `FULLTEXT (titulo, contenido)`; InnoDB crea solo los índices de las llaves foráneas |
| CHECK | Ninguno explícito; los `ENUM` restringen `rol`, `tipo` y `estado` |
| Triggers / vistas / procedimientos | **Ninguno.** Solo `ON UPDATE CURRENT_TIMESTAMP` en `perfiles.actualizado_en` y `publicaciones.actualizado_en` |
| Datos iniciales | 38 materias (catálogo de **ejemplo** de ISC, pendiente de validar con el plan del TESH) |
| Datos de demostración | 4 cuentas, 2 publicaciones y 1 respuesta ficticias, creadas por `instalar.php` (no por SQL) |
| Datos reales | Ninguno. La base local de XAMPP solo tiene datos de prueba |

## 2. Matriz de correspondencia de tipos

| MySQL | PostgreSQL | Motivo |
|---|---|---|
| `INT UNSIGNED AUTO_INCREMENT PRIMARY KEY` | `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | `INTEGER` no cubre el rango sin signo (hasta 4 294 967 295). `BY DEFAULT` permite importar ids existentes |
| `INT UNSIGNED` (llaves foráneas) | `BIGINT` | Mismo tipo que la llave referenciada |
| `INT UNSIGNED` (`adjuntos.tamano`) | `BIGINT` + `CHECK (tamano >= 0)` | Conserva rango y la semántica sin signo |
| `TINYINT UNSIGNED` (`semestre`) | `SMALLINT` + `CHECK (semestre BETWEEN 1 AND 12)` | La app ya solo acepta 1..12 (`perfil_editar.php`) |
| `TINYINT(1)` | `BOOLEAN` | `activo`, `usado`, `resguardada`, `es_imagen`, `resguardado` |
| `ENUM('a','b')` | `TEXT` + `CHECK (col IN (...))` | Más fácil de ampliar en una migración que un tipo `ENUM` |
| `VARCHAR(n)` | `VARCHAR(n)` | Se conservan los límites |
| `TEXT` | `TEXT` | Sin pérdida (PostgreSQL no tiene el límite de 64 KB) |
| `CHAR(64)` | `CHAR(64)` | Hash SHA-256 en hexadecimal |
| `DATETIME DEFAULT CURRENT_TIMESTAMP` | `TIMESTAMPTZ DEFAULT now()` | La app usa `America/Mexico_City`; la sesión de PHP fija esa zona |
| `ON UPDATE CURRENT_TIMESTAMP` | Trigger `nexo.fijar_actualizado_en()` (V002) | Solo cambia la fecha si alguna columna cambió, como MySQL |
| `UNIQUE (correo)` con `_ci` | `UNIQUE (correo)` + `CHECK (correo = lower(correo))` | La app siempre guarda en minúsculas; así `WHERE correo = ?` usa el índice |
| `UNIQUE (nombre, carrera)` con `_ci` | `UNIQUE INDEX (lower(nombre), lower(carrera))` | Misma unicidad sin distinguir mayúsculas |
| `FULLTEXT (titulo, contenido)` | `GIN (to_tsvector('spanish', titulo \|\| ' ' \|\| contenido))` | Búsqueda en español para el PBI-05 |
| Índices automáticos de FK (InnoDB) | `CREATE INDEX` explícitos en cada FK | PostgreSQL no los crea solo |
| `LIKE` con `_ci` (sin mayúsculas ni acentos) | `unaccent(col) ILIKE unaccent(?)` | Misma búsqueda de estudiantes; requiere la extensión `unaccent` (V000) |

## 3. Dependencias de la app PHP

| Archivo | Dependencia de MySQL | Cambio |
|---|---|---|
| `config/config.php` | Solo conexión MySQL | `DB_MOTOR` (`pgsql` por defecto o `mysql`) y `DB_PUERTO` |
| `includes/db.php` | DSN `mysql:` | DSN según motor; en PostgreSQL fija `search_path` y zona horaria. Nueva función `sql_contiene()` |
| `perfil_editar.php` | `INSERT ... ON DUPLICATE KEY UPDATE` | `UPDATE` o `INSERT` según exista el perfil (portátil) |
| `estudiantes.php` | `activo = 1`, `LIKE` | `activo = TRUE`, `sql_contiene()` |
| `perfil.php` | `resguardada = 0` | `resguardada = FALSE` |
| `recuperar.php` | `activo = 1` | `activo = TRUE` |
| `restablecer.php` | `usado = 0`, `usado = 1` | `usado = FALSE`, `usado = TRUE` |

`TRUE` / `FALSE` funcionan en MySQL (equivalen a 1 / 0) y en PostgreSQL, así que la app sigue funcionando con ambos.
El resto de las consultas ya era SQL estándar (`LIMIT ... OFFSET`, subconsultas, `lastInsertId()`).

## 4. Qué no se migró y por qué

- **Datos de demostración:** necesitan `password_hash()` de PHP; se siguen creando con `nexo/instalar.php`.
- **Datos de la base MySQL local:** solo eran pruebas ficticias; no hay datos reales que trasladar.
- **Diagramas** (`diagrama_entidad_relacion.drawio`, `modelo_relacional.drawio`): el modelo E-R no cambia. El modelo relacional se
  actualizó el 02/11/2026 con los tipos de PostgreSQL; los de MySQL están en la matriz de arriba.
